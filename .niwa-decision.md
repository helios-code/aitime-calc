# .niwa-decision — task 5f028766 (visual QA EN+FR)

ROOT_CAUSE: The `qa/visual` harness drove the app EN-only; today's merge train shipped FR/EN i18n,
so FR (strings ~20% longer) had no automated visual coverage — overflow/truncation/mixed-language in
FR would ship unseen.

DECISION: Extend the harness minimally instead of forking it — add a `LOCALE` env that appends the
app's own `?lang=` permalink param (i18n.LANG_PARAM) to each swept route in `baseline.mjs` +
`overflow.mjs`. Kept the functional click-through EN-only (its button-name matchers are English
literals; localizing them would be scope creep and brittle). Ran both locales, committed the audit
report `docs/audits/visual-qa-2026-08-07.md`. Layout is clean in both locales on every surface
(docOverflow=0 everywhere), so **no CSS fixes were needed or made**. The three findings are FR
mixed-language content gaps (F1/F2 duration + "classic software generations" untranslated, F3 axis
suffix) — string/formatter logic, **non-trivial**, so reported only and escalated to cto per the
ticket's "non-trivial → report only" rule. Screenshots stay git-ignored (nothing binary committed).
