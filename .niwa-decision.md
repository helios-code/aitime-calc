# Task fbce7ca6 — Frontend: show API version in web footer

ROOT_CAUSE: The web app never surfaced which API version was serving it; users/devs had no way to see the running version, and there was no shared footer to host that or future site-wide chrome.

DECISION: Added `fetchHealth()` to `web/src/lib/api.ts` mirroring the existing live/mock pattern (2s timeout, returns `string | null`, swallows all failures) against the `{status:'ok', version, uptime_s}` contract — backend is built in parallel, so tests mock it and the UI never blocks on a live API. Introduced one shared `SiteFooter` component (self-fetches the version, renders an em-dash on any failure) rendered on all five SiteNav surfaces (home + compare + timeline + leaderboard + methodology; /embed stays chrome-free by design). Kept it a separate slim footer rather than mutating each page's existing per-page `app-footer` (source badges) to avoid touching page-specific content and to give a single source of truth for site chrome.
