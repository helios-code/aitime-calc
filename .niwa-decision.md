# Task ecfb9b3c — /api/health endpoint (Fastify)

ROOT_CAUSE: An `/api/health` route already existed in `api/src/server.ts` but returned the wrong shape — `{ ok: true, version }` — with no `uptime_s` and a boolean `ok` instead of the `status: 'ok'` string the web footer / monitoring contract requires.

DECISION: Reshaped the existing route to return `{ status: 'ok', version, uptime_s }` rather than adding a second route.
- `version`: reuses the module-level `PKG_VERSION`, parsed once from `api/package.json` at boot (line ~18) — no per-request fs read.
- `uptime_s`: `Math.floor(process.uptime())` computed at request time — integer, >= 0.
- Updated the existing `GET /api/health` test to assert the new body shape (status/version/uptime_s) instead of `ok`.

ALTERNATIVES REJECTED:
- Add a new route and leave the old one: rejected — two health routes, duplicate path, confusing contract.
- Keep `ok: true` alongside `status`: rejected — spec fixes the shape as `{status, version, uptime_s}`; extra field is noise. No web consumer reads `.ok` (grep clean).
- Read package.json version per request: rejected — wasteful fs read; boot-time constant already exists.
