## Findings (mixed-language — content, not layout)

FR pages leak untranslated English in three spots. All are **string/formatter logic (non-trivial)**, not
CSS — per the ticket these are **reported only, escalated to cto as tickets-to-be**, not fixed in this
branch.

- **F1 — major — "classic software generations" subheadline untranslated in FR.**
  The hero subline `≈ N classic software generations` stays English on `/` and `/compare` (both cards),
  and bleeds into the **share/copy/embed text** (`… ≈ 4.7 classic software generations`).
  Surfaces: home, compare, embed, share strings.

- **F2 — major — duration values render English units in FR.**
  The duration humanizer is not locale-aware: `il y a 1 yr 9 mo`, `28 years 3 months` (home),
  `7 yrs 6 mo` / `6 yrs 2 mo` (compare "ÉCOULÉ"). Mixes with the surrounding FR copy and leaks into the
  FR share text (`… compressées en 1 yr 9 mo`). Surfaces: home, compare, share strings.

- **F3 — minor — timeline Y-axis tick suffix.**
  `/timeline` Y-axis ticks keep the English `y` suffix in FR (`120y / 60y / 12y / 0y`).

**Not a defect (noted for completeness):** tool *descriptions* (e.g. "Cursor's autonomous 'YOLO mode'
agent execution feature.") stay English in FR — these are API **source data / content**, outside the UI
i18n string layer. Flagging as by-design, not a bug; a product call if FR descriptions are wanted.
