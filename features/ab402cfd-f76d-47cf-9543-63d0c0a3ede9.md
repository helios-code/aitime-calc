## 2. Root cause & decisions

# niwa-decision — FR/EN i18n (task ab402cfd)

ROOT_CAUSE: The concept/README are French (native market) but the entire web UI was
hardcoded English, with no way to switch — a monolingual site for a bilingual audience.

DECISION — dependency-light, no i18next:

**Library choice.** Hand-rolled typed strings map + `t` over i18next. For ~6 pages the
runtime/bundle/config cost of i18next isn't worth it, and a plain typed object gives a
stronger guarantee: `fr` is declared `: Strings` (the shape of `en`), so a missing or
misnamed translation is a **compile error**, not a silent English fallback. Interpolations
are plain functions in the map (e.g. `leaderboard.caption(dir, label)`), so no template
DSL. Dataset notes/names are DATA and stay English — never routed through `t`.

**Locale resolution** (`resolveLocale`, pure + unit-tested): `?lang` param > localStorage
> `navigator.language` startsWith('fr') > `en`. Resolved ONCE at module load into `LOCALE`.

**Toggle = persist + full navigation.** `setLocale` writes localStorage, sets `?lang`, and
does `window.location.assign`. This app renders from module-load constants with no context
provider; a full reload is the simplest way to guarantee **no mixed-language screen** (DoD).
The trade (a reload on toggle, rare) is worth the simplicity and correctness.

**?lang × urlState.** `lang` is orthogonal to the compare/timeline params in urlState — those
decoders ignore it, and `setLocale` preserves existing query params when it sets `lang`, so a
compare permalink keeps its `tool`/`vs`/`model` across a language switch. In-app nav links
don't carry `lang`; localStorage persistence covers navigation, and `?lang` stays for
copy-paste sharing.

**Methodology page** is a translated document, so its dense prose (inline `<code>`/`<strong>`/
formulas) lives as whole per-locale JSX nodes in `web/src/content/methodology.tsx`, selected by
`LOCALE` — not atomised into the flat map. Code identifiers, formulas and numeric constants are
identical in both locales (data, never translated); technical terms kept exact.

**/embed** strings translate via `t` (it respects the same resolution) but it stays chrome-free
— no nav, no footer, no toggle. A host controls its locale via `?lang` on the embed URL /
its own navigator; the embed snippet is left locale-neutral by design.

**Scope hygiene.** Removed the now-dead `SORT_LABELS` (leaderboardSort.ts) — its only consumer
now reads `t.leaderboard.sortLabels`, keeping a single source for those labels.

TESTS: `i18n.test.ts` covers the full resolution precedence (param > stored > navigator > en),
invalid-value skip, and `isLocale`. FR completeness is enforced at compile time by the
`Strings` type. All existing web tests untouched and green.
