## 2. Root cause & decisions

# niwa-decision — A11y: sync <html lang> with active locale (task 959d4c9f)

ROOT_CAUSE: `web/index.html` ships `lang="en"`. When the UI renders French (?lang=fr,
stored choice, or fr browser), the document language attribute stays `en`, so screen
readers announce French content with an English speech engine — an a11y defect surfaced
as a non-blocking gate finding on ab402cfd (merged 3b8fb68c).

DECISION:

- Add `syncDocumentLang(locale)` in `web/src/lib/i18n.ts` — sets
  `document.documentElement.lang = locale`, guarded by a `typeof document` check so it is
  SSR/test-safe. Called once at module load with `LOCALE`.
- Load-time set is sufficient: the language toggle (`setLocale`) does a full navigation
  (`window.location.assign`), so every locale change re-runs the module and re-syncs. The
  function is still exported/reusable if an in-place switch is ever added.
- No new dependency, no render path touched — pure module side-effect matching the
  existing "resolve once at module load" i18n design.

TESTS (`web/src/lib/i18n.test.ts`):
- `syncDocumentLang` sets `documentElement.lang` for both `en` and `fr`.
- Module-load integration: `vi.resetModules()` + `history.replaceState('/?lang=fr')` +
  dynamic `import('./i18n')` yields `documentElement.lang === 'fr'`; same for `en`.

ALTERNATIVES REJECTED:
- Hardcoding `lang="fr"` in index.html — wrong for EN users.
- A React `useEffect` in App — later than module load, adds a render-path dependency for
  what is a one-line document attribute; the toggle-reloads model makes it unnecessary.

VERIFICATION: `npm run test` 117 passed (16 files), `npm run build` (tsc -b + vite) green.
